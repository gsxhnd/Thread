# Thread / 灰线 — 技术选型

> 本文对应 [00.overview.md](00.overview.md) 第 7 节「待确认问题」的最终结论，作为后续开发的技术基线。

---

## 1. 总览

| 层次 | 选型 | 说明 |
| --- | --- | --- |
| 桌面框架 | **Tauri v2**（Rust） | 体积小、内存低，系统集成能力强 |
| 前端框架 | **React 18 + TypeScript** | 生态成熟，团队熟悉 |
| 构建工具 | **Vite** | Tauri 官方推荐，HMR 快 |
| UI 组件 | **shadcn/ui**（Radix UI + Tailwind CSS） | 可控源码、无运行时锁定 |
| 富文本编辑器 | **TipTap** + `tiptap-markdown` | 正文以 Markdown 存储 / 导出 |
| 状态管理 | **Zustand** | 轻量、样板代码少 |
| 数据请求/缓存 | **TanStack Query**（可选） | 封装 IPC 异步、缓存与失效 |
| 路由 | **TanStack Router** | 类型安全，适合桌面单窗口多视图 |
| 本地数据库 | **SQLite** via `tauri-plugin-sql` | local-first，零配置随应用分发 |
| AI | **OpenAI 兼容 API + BYOK** | 用户自带 Key，支持自定义 baseURL |
| 包管理 | **pnpm** | 快、省盘，monorepo 友好 |

## 2. 待确认问题结论

### 2.1 编辑器框架 → TipTap（Markdown 存储）

选择 **TipTap**（基于 ProseMirror），理由：

- 生态丰富，扩展（表格、任务列表、协同等）齐全，社区活跃。
- 可通过 **`tiptap-markdown`** 扩展实现 Markdown 双向转换：
  - 读取：`editor.storage.markdown.getMarkdown()`
  - 写入：以 Markdown 字符串作为 `content` 初始化，或 `setContent(md)`
- 如需更精细的规则，可退回底层使用 `prosemirror-markdown` 的 `MarkdownSerializer` / `MarkdownParser` 自定义。

**存储策略**：章节正文在数据库中以 **Markdown 文本** 落库（见 [03.database.md](03.database.md)），既满足概述「导出 Markdown」需求，也便于全文检索与版本对比。编辑器内部运行时使用 ProseMirror 文档模型，保存时序列化为 Markdown。

> 备选：Lexical（Meta 出品、性能好），但 Markdown 生态与扩展成熟度不及 TipTap，暂不采用。

### 2.2 存储 → SQLite via `tauri-plugin-sql`

- 使用官方 **`tauri-plugin-sql`**（底层 `sqlx`），前端可直接执行 SQL，也可在 Rust 侧封装 service。
- **local-first**：数据库文件存于应用数据目录（`$APPDATA/thread/thread.db`）。
- 迁移通过插件的 migrations 机制管理（见 [03.database.md](03.database.md)）。

> 备选：Rust 侧 `rusqlite`。若后续需要复杂事务/自定义函数再评估切换；当前 `tauri-plugin-sql` 足够。

### 2.3 AI → OpenAI 兼容 API + BYOK

- 采用 **OpenAI 兼容 API** 协议（`/v1/chat/completions`），用户可配置：
  - `baseURL`（支持 OpenAI、DeepSeek、Ollama 的兼容端点、其他兼容服务）
  - `apiKey`（**BYOK**，用户自带 Key）
  - `model`
- **Key 安全**：不明文写入普通配置，优先使用系统钥匙串（`tauri-plugin-stronghold` 或 OS keychain）；最低要求也需与业务库隔离存储。
- AI 请求统一经 **Rust 后端** 代理转发（避免前端直连暴露 Key、便于统一超时/重试/流式处理），见 [02.architecture.md](02.architecture.md) 与 [04.ipc-api.md](04.ipc-api.md)。

### 2.4 云同步 → 暂缓（Phase 5）

- 首版聚焦 local-first，**云同步暂缓**至路线图 Phase 5。
- 预留设计：所有实体带 `updated_at` 与软删除标记，为将来基于时间戳/CRDT 的同步留出空间。

## 4. 版本与兼容性约定

- Node ≥ 20，pnpm ≥ 9，Rust stable（≥ 1.77），Tauri CLI v2。
- 目标平台：macOS、Windows、Linux（详见 [06.dev-guide.md](06.dev-guide.md)）。
- 具体锁定版本以初始化工程时的 lockfile 为准，本文只约定大版本方向。
