## 1. 目录结构

```text
crates/app/src/
├── main.rs               # 入口：AppCore 初始化 → gpui_kit::application → open_window
├── app.rs                # AppView 根视图：标题栏 + 侧边栏 + 内容区；请求标签页（RequestTab）
├── state.rs              # WorkspaceModel（Entity）：工作区快照 + 外部修改监听；MainView 导航枚举
├── theme.rs              # 主题偏好（System/Light/Dark）持久化 + Theme::change 切换
├── format.rs             # 展示格式化：方法/状态语义色、时间、字节数
├── widgets.rs            # 跨视图小组件：空状态、区块卡片、MethodTag/StatusTag（RenderOnce）
└── views/
    ├── content.rs        # 内容区分发：MainView → 各视图 render
    ├── welcome.rs        # 欢迎页：打开/新建工作区 + 最近列表
    ├── sidebar.rs        # 侧边栏（手写布局）：身份头 + 导航 + 集合树（Tree/TreeState）
    ├── request.rs        # 请求视图：标签条 + 方法/URL/发送 + KV 编辑 + 请求体
    ├── response.rs       # 响应面板：状态行 + 响应体/响应头/Cookie/耗时
    ├── history.rs        # 历史视图：列表 + 详情
    ├── proxy.rs          # 代理视图：启停控制 + 抓包设置 + 流量列表 + 条目详情
    ├── environments.rs   # 环境视图：环境列表 + 变量编辑 + 激活
    ├── certificates.rs   # 证书视图：CA 信息 + 导出 + 再生成
    └── settings.rs       # 设置视图：外观、HTTP 默认值、本地数据路径
```

## 2. 分层与数据流

```
┌──────────────────────────── crates/app（GPUI，单窗口单实体） ──────────────────────┐
│  AppView（Entity）                                                                 │
│   ├── workspace: Entity<WorkspaceModel>   ← WorkspaceEvent::Changed/Failed        │
│   ├── tabs: Vec<RequestTab>               （每个 tab 持有 Select/Input/Editor）   │
│   └── proxy/history/environment/certificate 各视图状态                            │
└───────────────────────────────────┬────────────────────────────────────────────────┘
                                    │ core.spawn(tokio future) → oneshot::Receiver
┌───────────────────────────────────┴────────────────────────────────────────────────┐
│  crates/core：AppCore（领域编排，无 UI 依赖）                                        │
│   open/create_workspace · send_http · cancel_http · proxy.* · history.* · config   │
└─────────────────────────────────────────────────────────────────────────────────────┘
```

- **没有 IPC 边界**：Tauri command 层已下沉为 `thread-core` 的 `AppCore` 方法（见 [04.ipc-api.md](04.ipc-api.md) 的迁移说明）。
- **UI 状态 = 实体字段**：原 Zustand store 对应 `AppView` 的字段；所有变更走 `cx.notify()` 触发重绘。
- **服务端数据 = Entity**：原 React Query 缓存对应 `Entity<WorkspaceModel>` + 各视图的懒加载字段，`cx.subscribe_in` 监听变更。

## 3. 异步模式（tokio ↔ GPUI 桥）

`AppCore::spawn` 把 tokio future 丢到运行时并返回 `oneshot::Receiver<T>`；UI 侧用 `cx.spawn` 等待结果后回填实体：

```rust
let core = self.core.clone();
let task_core = self.core.clone();          // 避免 move 冲突：克隆两份
let receiver = core.spawn(async move { task_core.send_http(payload).await });
cx.spawn(async move |this, cx| {
    let result = receiver.await.map_err(...).and_then(|r| r);
    let _ = this.update_in(cx, |view, window, cx| {
        // 回填状态；window.push_notification(...) 需在此闭包内使用 window 参数
        cx.notify();
    });
})
.detach();
```

要点：

- `WeakEntity::update_in(cx, |view, window, cx| ...)` 接受 `&mut AsyncApp`，是异步回填 + 弹通知的标准入口。
- `Entity::update_in` 需要 `VisualContext`（`Context<T>` 不满足）；同步路径用 `Entity::update(cx, |state, cx| ...)`，需要 `&mut Window` 的调用（`set_value` / `set_selected_index`）通过闭包捕获外层 `window` 完成。
- 轮询类任务（代理事件、工作区外部修改）用 `cx.background_spawn` + `background_executor().timer()` 循环。

## 4. 主题与样式

- `theme.rs` 维护 `ThemePreference::{System,Light,Dark}`，持久化在 config 的 `ui_layout` 段；切换走 `Theme::change(mode, Some(window), cx)`。
- 颜色取自 `cx.theme()`（`ActiveTheme`）：`secondary` 当卡片底、`sidebar`/`sidebar_foreground` 用于侧边栏、`muted_foreground` 弱文本。
- 图标统一用 `gpui_kit::assets::IconName`（完整 Lucide 集，1830 枚），不要用 component 侧的同名旧枚举。

## 5. GPUI 版本相关 API 约定（0.7.3 / gpui-pre 0.3.9）

写代码时踩过并确认过的差异，避免再次踩坑：

| 约定 | 说明 |
| --- | --- |
| 分数间距命名 | `py_0p5` / `px_1p5`（不是 `py_0_5`） |
| 字重 | `.font_weight(FontWeight::SEMIBOLD)`（没有 `font_bold()`） |
| 尺寸档位 | `Sizable` 只有 `xsmall/small/large`（没有 `xxsmall`） |
| 滚动 | `overflow_y_scroll`/`overflow_x_scroll` 在 `StatefulInteractiveElement` 上，必须先 `.id()` |
| 空白 | 只有 `whitespace_normal/nowrap`，无 `whitespace_pre` |
| RenderOnce 组件 | 需要 `#[derive(IntoElement)]` 才能作为 child |
| 动态 id | `ElementId` 只有 `From<(&'static str, usize)>`；字符串 key 用 `SharedString::from(format!(...))` 形式 |
| `prompt_for_paths` | await 结果是双层 `Result`（oneshot 包平台 Result） |
| `Switch::on_click` | 回调签名 `Fn(&bool, &mut Window, &mut App)` |
| `Input` 的 placeholder | 设置在 `InputState::new(...).placeholder()` 上，`Input` 本身没有该方法 |
| `#[serde(flatten)]` 结构 | Rust 侧无字段别名，必须 `detail.summary.field` 访问 |

## 6. 与 core 的职责边界

- `crates/app` 不得直接读写工作区文件；一律通过 `thread_core::workspace::ops` / `AppCore` 方法。
- 通知（`window.push_notification`）只在 `update_in` 闭包内、有 `&mut Window` 时发出。
- `CaptureSettings` 等配置类型由 core re-export（`thread_core::services::proxy::CaptureSettings`），避免 app 依赖 core 内部模块路径。
