# Thread / 灰线 — 开发规范与构建发布

> 本文覆盖开发环境准备、常用脚本、代码规范、Git 提交规范、测试策略与打包发布。承接 [01.tech-stack.md](01.tech-stack.md) 的选型。

## 1. 环境准备

| 工具 | 版本 | 用途 |
| --- | --- | --- |
| Node.js | ≥ 20 | 前端构建运行时 |
| pnpm | ≥ 9 | 包管理 |
| Rust | stable ≥ 1.85 | Tauri 后端 |
| Tauri CLI | v2 | 开发/打包 |

各平台系统依赖（Tauri v2 前置）：

- **macOS**：Xcode Command Line Tools。
- **Windows**：Microsoft C++ Build Tools + WebView2 Runtime。
- **Linux**：`webkit2gtk`、`libayatana-appindicator`、`librsvg` 等（以发行版为准）。

```bash
# 安装 Rust（若未安装）
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh

# 安装 Tauri CLI
pnpm add -D @tauri-apps/cli
```

## 3. 常用脚本

在根 `package.json` 约定：

```jsonc
{
  "scripts": {
    "dev": "tauri dev",            // 启动桌面开发（前端 + Rust）
    "build": "tauri build",        // 打包各平台产物
    "web:dev": "vite",             // 仅前端调试（tauri.conf.json 的 beforeDevCommand）
    "web:build": "tsc && vite build", // 前端类型检查 + 构建（CI 使用）
    "typecheck": "tsc --noEmit",
    "test": "vitest run",          // 前端单元测试（工具函数 / store / 变量替换）
    "preview": "vite preview"
  }
}
```

> 包管理器：仓库内存在 `package-lock.json`，默认命令使用 `npm run <script>`；脚本本身与管理器无关，pnpm/yarn 亦可直接运行。

Rust 侧常用：

```bash
cargo fmt        # 格式化
cargo clippy     # 静态检查
cargo test       # 单元测试
```

## 4. 代码规范

### 4.1 前端

- **ESLint + Prettier**：提交前必须通过 `pnpm lint` 与 `pnpm typecheck`。
- **TypeScript**：开启 `strict`；避免 `any`，跨层类型集中在 `src/lib/api/types.ts`。
- **组件**：函数组件 + hooks；业务逻辑放 feature hooks，组件保持展示为主。
- **命名**：组件 `PascalCase`，hooks `useXxx`，文件与目录 `kebab-case` 或与导出一致。
- **IPC**：禁止在组件直接 `invoke`，统一走 `src/lib/api`（见 [04.ipc-api.md](04.ipc-api.md)）。
- **协议组件**：按功能域组织 `components/{domain}/`（request / response / grpc / websocket / mqtt / proxy）。

### 4.2 Rust

- **rustfmt + clippy**：CI 强制 `cargo fmt --check` 与 `cargo clippy -D warnings`。
- **分层**：command 只做校验与编排，逻辑落 service，数据访问落 repository（见 [02.architecture.md](02.architecture.md)）。
- **错误**：统一 `AppError`（`thiserror`），对外序列化为 `{ code, message }`。
- **异步**：所有网络操作使用 tokio async，避免阻塞主线程。代理引擎在独立 tokio task 运行。

## 5. Git 提交规范

采用 **Conventional Commits**：

```text
<type>(<scope>): <subject>

# 示例
feat(http): 支持 HTTP/2 请求
feat(proxy): 实现 HTTPS MITM 解密
fix(grpc): 修复 streaming 断连后未清理资源
docs(db): 补充代理条目表索引说明
```

- **type**：`feat` / `fix` / `docs` / `refactor` / `perf` / `test` / `chore` / `build` / `ci`。
- **scope**：模块名（`http`、`grpc`、`websocket`、`graphql`、`mqtt`、`proxy`、`cert`、`collection`、`env`、`history` ...）。
- **分支**：`main`（稳定）+ `feat/*` / `fix/*` 功能分支，经 PR 合并。
- 可选：引入 commitlint + husky + lint-staged 做提交前校验。

## 6. 测试策略

| 层次 | 工具 | 范围 |
| --- | --- | --- |
| 前端单元 | **Vitest** | 工具函数、hooks、store、环境变量替换 |
| 前端组件 | **@testing-library/react** | 关键组件交互 |
| Rust 单元 | `cargo test` | service / repository / 迁移 / 协议 client |
| Rust 集成 | `cargo test` (integration) | 代理引擎端到端、gRPC 调用链 |
| 端到端（可选） | **Tauri WebDriver** | 关键用户流程 |

- 优先覆盖：HTTP 请求发送与响应解析、环境变量替换、代理 MITM 证书生成、Proto 文件解析、数据库迁移。
- CI 中运行 `lint`、`typecheck`、`test`、`cargo fmt --check`、`cargo clippy`、`cargo test`。

## 7. 构建与发布

### 7.1 打包

```bash
pnpm build   # 等价 tauri build
```

产物（各平台）：

- **macOS**：`.app` / `.dmg`
- **Windows**：`.msi` / `.exe`（NSIS）
- **Linux**：`.AppImage` / `.deb`

### 7.2 版本与发布

- 版本号遵循 **SemVer**，`src-tauri/tauri.conf.json` 与 `package.json` 保持一致。
- 建议用 GitHub Actions 做多平台矩阵构建，产物上传 Release。
- **自动更新**（可选）：Tauri v2 `updater` 插件；需配置签名密钥与更新清单，留作后续。
- **代码签名**：macOS 需 Apple 开发者证书 + 公证，Windows 需代码签名证书（发布前配置）。

### 7.3 代理功能特殊说明

- 代理 MITM 需要用户安装并信任 CA 根证书，首次使用时引导。
- macOS 安装 CA 证书可能需要 `sudo security add-trusted-cert`，需在发布文档中注明。
- Windows / Linux 下的证书安装方式不同，需分平台文档。
