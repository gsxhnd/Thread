# Thread / 灰线 — 开发规范与构建发布

> 本文覆盖开发环境准备、常用脚本、代码规范、Git 提交规范、测试策略与打包发布。承接 [01.tech-stack.md](01.tech-stack.md) 的选型。

---

## 1. 环境准备

| 工具 | 版本 | 用途 |
| --- | --- | --- |
| Node.js | ≥ 20 | 前端构建运行时 |
| pnpm | ≥ 9 | 包管理 |
| Rust | stable ≥ 1.77 | Tauri 后端 |
| Tauri CLI | v2 | 开发/打包 |

各平台系统依赖（Tauri v2 前置）：

- **macOS**：Xcode Command Line Tools。
- **Windows**：Microsoft C++ Build Tools + WebView2 Runtime。
- **Linux**：`webkit2gtk`、`libayatana-appindicator`、`librsvg` 等（以发行版为准）。

```bash
# 安装 Rust（若未安装）
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh

# 安装 Tauri CLI
pnpm add -D @tauri-apps/cli
```

## 2. 初始化与目录

工程初始化后应形成 [00.overview.md](00.overview.md) §5 的结构：`src/`（前端）+ `src-tauri/`（Rust）+ `docs/`。数据库迁移放 `src-tauri/migrations/`（见 [03.database.md](03.database.md)）。

> 初始化脚手架不在文档阶段进行；确认文档后另开任务执行 `create-tauri-app` 或手动搭建。

## 3. 常用脚本

在根 `package.json` 约定：

```jsonc
{
  "scripts": {
    "dev": "tauri dev",           // 启动桌面开发（前端 + Rust）
    "build": "tauri build",       // 打包各平台产物
    "web:dev": "vite",            // 仅前端调试
    "lint": "eslint .",
    "format": "prettier --write .",
    "typecheck": "tsc --noEmit",
    "test": "vitest"
  }
}
```

Rust 侧常用：

```bash
cargo fmt        # 格式化
cargo clippy     # 静态检查
cargo test       # 单元测试
```

## 4. 代码规范

### 4.1 前端

- **ESLint + Prettier**：提交前必须通过 `pnpm lint` 与 `pnpm typecheck`。
- **TypeScript**：开启 `strict`；避免 `any`，跨层类型集中在 `src/lib/api/types.ts`。
- **组件**：函数组件 + hooks；业务逻辑放 feature hooks，组件保持展示为主。
- **命名**：组件 `PascalCase`，hooks `useXxx`，文件与目录 `kebab-case` 或与导出一致。
- **IPC**：禁止在组件直接 `invoke`，统一走 `src/lib/api`（见 [04.ipc-api.md](04.ipc-api.md)）。

### 4.2 Rust

- **rustfmt + clippy**：CI 强制 `cargo fmt --check` 与 `cargo clippy -D warnings`。
- **分层**：command 只做校验与编排，逻辑落 service，数据访问落 repository（见 [02.architecture.md](02.architecture.md)）。
- **错误**：统一 `AppError`（`thiserror`），对外序列化为 `{ code, message }`。

## 5. Git 提交规范

采用 **Conventional Commits**：

```text
<type>(<scope>): <subject>

# 示例
feat(editor): 接入 TipTap Markdown 序列化
fix(chapter): 修复切换章节时 autosave 丢字
docs(db): 补充伏笔表状态流转说明
```

- **type**：`feat` / `fix` / `docs` / `refactor` / `perf` / `test` / `chore` / `build` / `ci`。
- **scope**：模块名（`editor`、`chapter`、`foreshadowing`、`ai` ...）。
- **分支**：`main`（稳定）+ `feat/*` / `fix/*` 功能分支，经 PR 合并。
- 可选：引入 commitlint + husky + lint-staged 做提交前校验。

## 6. 测试策略

| 层次 | 工具 | 范围 |
| --- | --- | --- |
| 前端单元 | **Vitest** | 工具函数、hooks、store、Markdown 序列化 |
| 前端组件 | **@testing-library/react** | 关键组件交互 |
| Rust 单元 | `cargo test` | service / repository / 迁移 |
| 端到端（可选） | **Tauri WebDriver** | 关键写作流程 |

- 优先覆盖：autosave（防抖/flush/丢字）、伏笔状态流转、Markdown 双向转换、数据库迁移。
- CI 中运行 `lint`、`typecheck`、`test`、`cargo fmt --check`、`cargo clippy`。

## 7. 构建与发布

### 7.1 打包

```bash
pnpm build   # 等价 tauri build
```

产物（各平台）：

- **macOS**：`.app` / `.dmg`
- **Windows**：`.msi` / `.exe`（NSIS）
- **Linux**：`.AppImage` / `.deb`

### 7.2 版本与发布

- 版本号遵循 **SemVer**，`src-tauri/tauri.conf.json` 与 `package.json` 保持一致。
- 建议用 GitHub Actions 做多平台矩阵构建，产物上传 Release。
- **自动更新**（可选）：Tauri v2 `updater` 插件；需配置签名密钥与更新清单，留作后续。
- **代码签名**：macOS 需 Apple 开发者证书 + 公证，Windows 需代码签名证书（发布前配置）。
