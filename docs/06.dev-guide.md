## 4. 代码规范

### 4.1 UI（crates/app，GPUI）

- **rustfmt + clippy**：CI 强制 `cargo fmt --check` 与 `cargo clippy -D warnings`。
- **分层**：视图只做渲染与事件绑定，业务编排落在 `AppCore` / `workspace::ops`；禁止在 app crate 直接读写工作区文件。
- **异步**：统一走 `core.spawn(future)` → `cx.spawn` → `WeakEntity::update_in` 回填模式（见 [05.frontend.md](05.frontend.md) §3）。
- **命名**：视图模块 `snake_case`；小组件用 `RenderOnce` 结构体并 `#[derive(IntoElement)]`。

### 4.2 领域层（crates/core）

- **零 UI 依赖**：不得引用 gpui/gpui-kit；对外类型全部 `Send + Sync` 或纯数据。
- **错误**：统一 `AppError`（`thiserror`）。
- **异步**：所有网络操作使用 tokio async，避免阻塞；代理引擎在独立 tokio task 运行。

## 5. Git 提交规范

采用 **Conventional Commits**：

```text
<type>(<scope>): <subject>

# 示例
feat(http): 支持 HTTP/2 请求
feat(proxy): 实现 HTTPS MITM 解密
fix(grpc): 修复 streaming 断连后未清理资源
docs(db): 补充代理条目表索引说明
```

- **type**：`feat` / `fix` / `docs` / `refactor` / `perf` / `test` / `chore` / `build` / `ci`。
- **scope**：模块名（`http`、`grpc`、`websocket`、`graphql`、`mqtt`、`proxy`、`cert`、`collection`、`env`、`history`、`ui` ...）。
- **分支**：`main`（稳定）+ `feat/*` / `fix/*` 功能分支，经 PR 合并。

## 6. 测试策略

| 层次 | 工具 | 范围 |
| --- | --- | --- |
| core 单元/集成 | `cargo test`（`crates/core/tests/*_flow.rs`） | service、HTTP/代理/gRPC 链路、迁移 |
| UI 编译期保障 | `cargo clippy --all-targets -D warnings` | 全量视图类型检查 |
| 端到端（可选） | 手动冒烟 | 关键用户流程 |

- 优先覆盖：HTTP 请求发送与响应解析、环境变量替换、代理 MITM 证书生成、Proto 文件解析、数据库迁移。
- CI 中运行 `cargo fmt --check`、`cargo clippy`、`cargo test`。

## 7. 构建与发布

### 7.1 打包

```bash
cargo build --release -p thread-app
```

产物（各平台，后续按需接安装包工具）：

- **macOS**：可执行文件 → `.app` / `.dmg`
- **Windows**：`.exe`（MSVC）
- **Linux**：可执行文件 → `.AppImage` / `.deb`

### 7.2 版本与发布

- 版本号遵循 **SemVer**，统一在根 `Cargo.toml` `[workspace.package]`。
- 建议用 GitHub Actions 做多平台矩阵构建，产物上传 Release。
- **自动更新**（可选）：留作后续评估。
- **代码签名**：macOS 需 Apple 开发者证书 + 公证，Windows 需代码签名证书（发布前配置）。

### 7.3 代理功能特殊说明

- 代理 MITM 需要用户安装并信任 CA 根证书，首次使用时引导。
- macOS 安装 CA 证书可能需要 `sudo security add-trusted-cert`，需在发布文档中注明。
- Windows / Linux 下的证书安装方式不同，需分平台文档。
