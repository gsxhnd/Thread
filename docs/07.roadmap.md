# Thread / 灰线 — 开发路线图

> 本文是目标产品的实施计划，不代表功能已实现。产品范围见 [产品概述](00.overview.md)，技术基线见 [技术选型](01.tech-stack.md)，文件格式与本地数据设计见 [数据存储设计](03.database.md)。

## 当前状态与原则

- **阶段 0 与阶段 1 已实现**，实现记录、实测数据与验收对照见 [重构基线、工作区约定与阶段 1 实现记录](08.refactor-baseline.md)。阶段 2 及以后仍为规划，不代表已实现。
- 原写作工具的页面、Rust 命令与数据模型已按阶段 0 移除；旧数据保留在本地库中，可通过导出功能读取（不删除、不改名）。
- 保持 Tauri v2 + Rust、React + TypeScript、shadcn/ui + Tailwind CSS；编辑器目标为 Monaco Editor。网络请求和代理运行在 Rust 侧，前端通过 Tauri IPC 交互。
- 集合、请求和可共享环境配置采用工作区内文件作为 Git 跟踪的源数据；**阶段 0 实测后决定阶段 1 不引入 SQLite 文件索引**（扫描 1200 个请求文件约 53 ms，复核条件见 08 文档 §4）。请求历史、代理流量等本地数据仍使用 SQLite，且这些数据不是由工作区文件重建的索引，不可因索引重建而直接清除。
- 先打通一条可用的请求链，再增加协议与代理能力；每阶段以验收条件为完成标准，不预设日期。

## 阶段 0：重构基线与存储验证

> 状态：**已实现**（验收对照见 [08.refactor-baseline.md](08.refactor-baseline.md) §7）。

**目标**：移除产品方向上的耦合，确定 Git 友好的工作区约定。

- 盘点并逐步替换写作领域的路由、页面、模型、Rust 命令与迁移；明确旧数据保留/导出的处置方式，避免直接删除用户数据。
- 约定工作区目录、请求/集合/环境文件格式、版本号、稳定 ID、文件名冲突与原子写入方式；区分可入库配置与不应提交的密钥/运行数据。
- 做文件扫描、搜索、外部编辑及 `git pull` 后刷新的原型和性能测试，再决定是否引入 SQLite 文件索引；对已有本地历史/代理数据保持独立存储。
- 建立桌面启动、前端类型检查、Rust 测试的最小验证链。

**验收**：可创建和重新打开工作区；在应用外修改/切换 Git 分支后可刷新请求列表；工作区文件可直接查看和 diff；旧数据处置路径明确。

## 阶段 1：HTTP MVP

> 状态：**已实现**（能力矩阵与验收对照见 [08.refactor-baseline.md](08.refactor-baseline.md) §6–§7；已知限制见 §8）。

**目标**：完成从编辑、发送到保存、重开的完整闭环。

- Rust 执行 HTTP/HTTPS 请求：方法、URL、Query、Headers、JSON/Raw/Form/文件 Body、超时、取消、重定向与证书校验选项；响应展示状态、Headers、Body、大小和总耗时。
- 使用 Monaco Editor 编辑请求体并只读展示响应；实现请求标签页、集合/文件夹管理和基本搜索。
- 实现环境切换与 `{{variable}}` 替换，限定变量作用域和缺失变量提示。
- **完整请求/响应历史**：每次发送同时落盘请求内容（变量替换后的实际发出值）与响应内容（含 Body）；历史页可对照查看、重发、另存到集合；支持 Body 限额、脱敏与清理策略。这是相对常见工具「历史主要只留响应」的差异化能力。
- 工作区配置写入文件；历史与请求/响应体文件写入本地数据目录，不自动进入 Git。

**验收**：使用本地测试服务完成 GET、JSON POST、文件上传、超时/取消测试；重启后集合与环境不丢失；Git 只显示预期的配置文件变更；任选一条历史记录，能完整还原当时请求 Body/Headers 与响应 Body，并成功重发。

## 阶段 2：多协议请求测试

**目标**：在统一的集合与环境体验中覆盖五类协议。

1. **GraphQL**：Query/Mutation、Variables、Headers、响应展示；随后加入 Schema introspection 与补全、Subscription。
2. **WebSocket**：连接/断开、文本与二进制消息、收发记录、异常断线与连接资源清理。
3. **gRPC**：`.proto` 文件加载与 Server Reflection 均可发现服务；先实现 Unary 和 Server Streaming，再实现 Client Streaming 与 Bidirectional Streaming；支持 metadata 与 TLS。
4. **MQTT**：Broker 连接/断开、订阅/取消订阅、发布、QoS、消息查看；覆盖 TCP、TLS 与 WebSocket 传输。

**验收**：每种协议有本地可重复运行的服务端/测试用例；gRPC 两种服务发现方式与四种调用模式均可验证；长连接在切换页面与退出应用时能正确释放。

## 阶段 3：基础抓包代理

**目标**：稳定捕获经显式配置的 HTTP/HTTPS 流量。

- 实现 HTTP 代理入口、CONNECT 隧道、会话生命周期和流量列表；支持按域名、方法、状态码过滤及详情查看。
- 引入本地 CA 的生成、导出、用户明确授权后的安装/信任引导与卸载说明；在可信任且允许解密的目标上实现 HTTPS MITM，未授权或无法解密时保持隧道转发并标明不可查看内容。
- 实现抓包暂停/继续、持久化开关、大小/条数上限、敏感字段隐藏及流量清理；代理关闭或异常退出后恢复被修改的系统代理设置。
- 先验证应用显式设置的代理地址；各平台系统代理自动配置作为独立验收项。

**验收**：本地 HTTP/HTTPS 客户端通过代理请求成功，能看到请求/响应摘要；关闭代理后网络配置恢复；未信任 CA 时不会宣称可解密 HTTPS。

## 阶段 4：SOCKS5 与高级代理

**目标**：覆盖另一种代理入口，并完成可控的调试规则。

- 实现 SOCKS5 客户端协商、目标连接与基础 TCP 转发；说明 SOCKS5 原始 TCP 流量与 HTTP/HTTPS 可解析流量的展示边界，不承诺任意协议自动解码。
- HTTP/HTTPS 流量增加请求/响应断点、放行/丢弃、Block/Allow、Rewrite、Map Local/Remote，并设置优先级、超时与规则冲突行为。
- 补齐 macOS / Windows / Linux 的系统代理设置与恢复测试，以及 CA 信任的跨平台操作说明。

**验收**：HTTP 与 SOCKS5 入口均可独立启停；断点超时不无限挂起连接；规则冲突和代理异常退出有可预测结果；系统设置可恢复。

## 阶段 5：脚本与自动化

**目标**：让请求集合可重复执行并验证结果。

- 评估并确定隔离的 JavaScript 运行时（候选 QuickJS），设计权限、超时、内存限制、日志与可用 API；默认不允许任意访问本地文件或网络。
- 实现前/后置脚本、变量写入、断言、集合运行器和失败报告；机密变量在日志与导出中脱敏。

**验收**：集合测试可重复运行并输出可定位的断言失败；脚本超时/异常不会卡死应用或泄露机密。

## 阶段 6：导入导出与发布

**目标**：降低迁移门槛，完成可分发版本。

- 按优先级支持 cURL、Postman Collection v2.1、OpenAPI 3.x 和 HAR 的导入/导出；明确不支持字段、转换损失及冲突处理。
- 完成跨平台安装包、升级兼容性、备份/恢复、文档与安全检查；Mock Server 在基础版本稳定后评估，不作为首个正式版阻塞项。

**验收**：导入样例可复核主要请求字段；升级后工作区可读；macOS、Windows、Linux 的请求发送与代理启停通过冒烟测试。

## 跨阶段约束与待验证项

- **Git 与机密**：工作区内的密码、Token、私钥不可因 UI 中标记 `secret` 就视为安全；落盘前需确定系统凭据库/本地忽略文件方案，并提供 `.gitignore` 模板。密钥方案未落地前，不将机密写入可提交文件。
- **SQLite 边界**：文件索引是可重建缓存；历史、代理会话、Cookie 等若存 SQLite，则是独立本地数据，需要自己的迁移、备份与清理规则。通过实测决定何时引入索引层。
- **代理范围**：本路线图的「抓包」是显式/系统代理模式，不等于网卡级抓包；证书固定、未配置代理的应用和非 HTTP 流量存在天然限制。
- **性能与隐私**：大响应体采用流式/限额处理；代理高频事件批量推送；默认不记录敏感 Body，清理策略与数据保留开关应可见。
- **测试优先级**：优先覆盖请求取消、文件写入与外部变更、长连接清理、MITM 信任边界、代理异常后的系统设置恢复。
